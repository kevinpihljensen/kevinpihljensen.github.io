# Changelog

This file tracks what has been built so each new chat session can resume without rediscovering state. Update it at the end of every session.

Format: newest entries at the top. Each entry lists what was added, what was changed, and what is known broken.

## Conventions

- One entry per chat session.
- Date in `YYYY-MM-DD` format.
- Three subsections per entry: **Added**, **Changed**, **Known issues**. Omit a subsection if empty.
- Be specific about file names and function names. "Added enemy AI" is useless; "Added `Grunt.update()` with pathfinding via direct vector toward player" is useful.
- Note any deviations from `design.md` or `controls.md`. Update those files in the same session if the deviation is intentional.

## Current State

**Milestone:** 15 + S55g RIDGEPOINT CITADEL redesign. The map is now RIDGEPOINT CITADEL (130×130, cohesive Quake-arena lens with a central tiered keep). Three play modes are selectable from the title screen: Wave (original 10-wave shooter), Arena (continuous-combat deathmatch with player + enemy respawn), Map Test (free roam, no enemies).
**Lines of code:** ~9100 across 19 modules
**File structure:** `index.html` + `src/{constants,state,scene,audio,collision,textures,kit,arena,decals,enemies,projectiles,weapons,player,wave,hud,input,pickups,main}.js` + `assets/audio/*.wav` + `build-singlefile.mjs`

> Modular build needs a static server OR GitHub Pages. `fps-standalone.html` (generated by `build-singlefile.mjs`) runs directly from `file://`.

> **M15 is COMPLETE.** Stage 1 (2.5D collision), Stage 2 (3 connected floors + cross-floor player/AI), Stage 3 (map pickups). Weapons are no longer unlocked by wave number; each non-pistol weapon spawns as a pickup on the map and is permanent for the run once collected. Passive health regen is gone — health pickups on the ground are the only way to recover HP.

**3. Realistic procedural textures (`textures.js`, `kit.js`).** Replaced the flat-color industrial palette with material-y surfaces, all still procedural (CanvasTexture, no external assets). New helpers in textures.js:

- `makeFloorTexture` — weathered concrete with hairline cracks, oil-stain gradients, mortar grooves, and per-pixel fbm shading.
- `makeBrickTexture` — running-bond brick (8 courses, 96 px brick width, 4 px mortar), per-brick random tint, top-highlight + bottom-shadow strips for fake bevel, weathering streaks.
- `makeWoodTexture` — vertical planks (6 wide) with grain stripes, knots, shadow strips between planks.
- `makeConcreteTexture` — smooth poured concrete (decks/ramps/overhangs).
- `makeMetalTexture` — brushed steel with diagonal scratches and tread-plate dots (stairs).

`kit.js` MAT entries now use these maps with sensible per-surface repeats: floor 20×20 (160 m ground / 8 m per tile), brick 2×1 on walls, wood 1×1 on cover crates, concrete 3×3 on decks. Legacy `makeWallTexture` / `makeInteriorWallTexture` / `makeCoverTexture` / `makePillarTexture` retained (now also using fbm internally) so any external import still works.

**4. Positional audio (`audio.js`, `main.js`, `enemies.js`).** Enemy gunfire now plays in 3D space via a WebAudio PannerNode (HRTF panning + inverse-distance falloff, `refDistance=6`, `maxDistance=140`, `rolloffFactor=1.4`). New helpers:
- `playSamplePositional(slot, x, y, z, detuneCents)` — wraps `playSample` through a fresh per-shot PannerNode positioned at the muzzle.
- `playNoisePositional(opts, x, y, z)` — synth-noise fallback if the sample failed to load (asset 404 in dev) so the spatial cue survives an asset miss.
- `updateAudioListener(px, py, pz, fx, fy, fz)` — called once per active frame from `main.js` (after the per-frame Vector3 forward computation) to keep `audioCtx.listener` synced with the camera. Modern AudioParam API + `setPosition`/`setOrientation` fallback for older browsers.

`sfxShooterFire(x, y, z)` accepts an optional position. When supplied, it routes through positional playback; when omitted, stays at the master bus (unchanged behaviour). All three enemy fire paths (`shooterFire`, `heavyFire`, `jetpackFire`) now pass the computed world muzzle. Player weapons stay non-positional (full volume / centred, which is how every FPS handles your own weapon).

### 2026-05-17 — Session 50 (Feel pass: per-weapon spray patterns, view-model sway/bob/lag, procedural reload animations)

User asked for closer-to-CS2 weapon feel. Honest scope-setting: matching CS2's polish fully would mean authored bone-rigged glb assets + PBR maps + HDR + multi-layer audio (months of work). What this session does is the 70% that is **pure code**: recoil that's a learnable pattern, a view-model that feels alive, and per-weapon procedural reload animations. Big perceived improvement, zero new assets.

**1. Per-weapon recoil patterns (`constants.js`, `weapons.js`, `player.js`).** Recoil is no longer a single decaying pitch value. `RECOIL_PATTERNS` defines a per-weapon list of `{p, y}` kicks (pitch + yaw, radians). `tryFire()` looks up `pattern[sprayIndex % length]`, adds the kick to both `wState.recoilPitch` and `wState.recoilYaw`, and increments `sprayIndex`. `RECOIL_RESET_TIME = 0.35 s` of not firing snaps `sprayIndex` back to 0 — so each new burst restarts the pattern, which is exactly what makes CS sprays learnable. Single-shot weapons (pistol/shotgun/sniper) get one-entry patterns; SMG has 12 shots; SAW has 15. Both pitch and yaw decay each frame via the existing `RECOIL_DECAY` so the camera returns to neutral when firing stops. Yaw is now applied to `camera.rotation.y` in `player.js` alongside the existing pitch. Switching weapons or resetting clears the spray.

Pattern shape (chosen by feel, not lifted from CS): SMG peaks pitch in the first half of the burst and alternates horizontal direction over ~10 sign flips (verified by harness); SAW does the same but heavier (peaks pitch shot 4, then heavy lateral drift). The patterns wrap with modulo so a 100-round SAW burst stays bounded — last entries are smaller so net drift converges.

**2. View-model sway / bob / lag (`constants.js`, `weapons.js`).** Each frame the active weapon's transform is composed by a new `updateViewModelTransform(dt)`:
- **LAG** — `dYaw` and `dPitch` since last frame drive a small horizontal/vertical position offset (`VIEW_SWAY_LAG = 0.040`, capped at `VIEW_SWAY_MAX = 0.035 m`), decaying back to zero (`VIEW_SWAY_DECAY = 12 /s`). Turn the camera right, the gun lags left briefly, eases back.
- **BOB** — figure-eight at footstep cadence (`VIEW_BOB_FREQ = 9 cycles/s`, `VIEW_BOB_AMP = 0.010 m`), scaled by horizontal movement speed (zero at standstill, peaks at sprint). Smoothed by a low-pass so the bob doesn't pop when grounded toggles.
- **LAND DIP** — feet snapping onto a surface drops the gun by `VIEW_LAND_DIP = 0.040 m`, eased back up (`VIEW_LAND_DIP_DECAY = 9`). Triggered on the airborne→grounded transition.

The whole thing composes against a captured `VIEW_MODEL_BASE` pose so it's stateless — each frame resets to the builder-set transform then adds the deltas. No drift.

**3. Procedural reload animations (`weapons.js`).** Each builder now tags its animated part via `userData.reloadPart`:
- pistol: `magBase` → `'mag'`
- shotgun: `pumpMesh` → `'pump'`
- SMG: `mag` → `'mag'`
- sniper: `bolt` + `boltKnob` → `'bolt'`
- SAW: `cover` → `'cover'`

After view-models are built, a `RELOAD_PARTS` map walks each model to find its tagged parts and captures their base pose. While `wState.reloadTimer > 0`, `updateViewModelTransform` computes `progress = 1 - reloadTimer/reloadDuration` (0→1) and runs the matching anim:
- **mag** — drops out (smoothstep 0.05–0.45), holds low (0.45–0.65), rises back in (0.65–0.95).
- **pump** — two back-and-forward strokes spread across the reload window (`_triangleN` helper).
- **bolt** — lift (rotate up, 0–0.20), pull back (0.20–0.55), push forward (0.55–0.85), lower (0.85–1.0).
- **cover** — hinges open (0–0.25), holds open (0.25–0.75), hinges closed (0.75–1.0).

The whole gun also tilts (`RELOAD_TILT_X`, `RELOAD_TILT_Z`) and dips (`RELOAD_DIP_Y`) during the reload, peaked on a `sin(πx)` hump so it eases in and out. Existing knife-swipe `meleeAnim` was folded into the same composition (was previously a separate write to `km.position.z`).

`tryReload` now stores `wState.reloadDuration` so the anim knows the total length even after `reloadTimer` ticks down.

**Verified.** Battery still ALL GREEN with the extended `harness_weapons.mjs`: 10 harnesses, **202 assertions** (+19). New assertions cover: `RECOIL_PATTERNS` shape + presence for every weapon, single-shot weapons have single-entry patterns, SMG/SAW have multi-entry, every entry has positive pitch + numeric yaw, at least one weapon has horizontal drift, SMG pitch peaks first half, SMG yaw alternates direction (≥3 sign flips), spray state machine (advance + reset after `RECOIL_RESET_TIME`, modulo wrap), and bounds on the new view-sway / reload-anim tunables.

**1. Jumping under a raised floor flung the player sideways.** Two coupled bugs:

**Known issues**
- **Requires HTTP server now.** Double-clicking `index.html` from a file system will fail to load `src/main.js` (browser CORS for ES modules). Documented in the HTML header comment. Run `python3 -m http.server` from the build dir and open `http://localhost:8000/`.
- **Bhop tuning is approximate.** The numbers (`AIR_WISH_SPEED_CAP=1.8`, `AIR_ACCEL=4.0`, `GROUND_FRICTION=6.0`) are in the right ballpark for Source-style movement but you'll likely want to tune them by feel. Higher `AIR_WISH_SPEED_CAP` makes air-strafing easier but raises the speed ceiling. Higher `GROUND_FRICTION` makes ground-contact land you closer to wish-speed (less bhop carryover).

- **Audio context can be suspended by the browser on tab blur** (carried over from m9).

Shared `SphereGeometry` + `MeshBasicMaterial`. Spawn at shooter chest (`SHOOTER_MUZZLE_Y = 1.2`); target = player chest (`(crouching ? EYE_HEIGHT_CROUCH : EYE_HEIGHT_STAND) * 0.6` above feet). Module-level `_projStep` reused per frame.
- Projectile collision: 2D radial vs player + Y-range gate so jumping/crouching can dodge. 2D AABB vs static obstacles (projectile flies at chest height in practice, always within wall 4m and cover 2m heights).
- Player health: `PLAYER_MAX_HEALTH = 100`, `REGEN_RATE = 10` HP/s, `REGEN_DELAY = 5.0s` after damage before regen resumes. `damagePlayer(amount)`: subtracts HP, resets regen delay, sets damage flash timer, calls `killPlayer()` if hp ≤ 0. `killPlayer()`: sets `player.alive = false`, `gameState = GAMEOVER`, shows the Game Over overlay, exits pointer lock. Both no-op if player is already dead.
- Player knockback: `player.impulse` (Vector3). Added to per-frame movement: `tmpMove.x += impulse.x * dt`. Exponential decay each frame at `IMPULSE_DECAY = 6/s`. Zeros out below 1e-3 so it doesn't linger.
- Damage feedback: `#damage-vignette` div, fixed inset 0, radial gradient (transparent center → red edges), z-index 4. Opacity ramps to 1.0 on hit, decays linearly over `DAMAGE_FLASH_TIME = 0.3s`. Updated in `updatePlayer()`.
- Game state machine: `GAME_STATE` enum { TITLE, PLAYING, PAUSED, GAMEOVER }. `gameState` variable gates `tick()` updates and routes the overlay-click handler (GAMEOVER → `location.reload()`; else → `startGame()`).
- `pointerlockchange` handler now checks `gameState`: if GAMEOVER, leaves the Game Over overlay alone instead of overwriting it with "Paused".

**Changed**
- Per-enemy AABBs **no longer pushed into `staticAABBs`** (deferred refactor from m5). `staticAABBs` now truly contains walls + covers only. Enemy AABBs are tested separately inside `moveCircle()` via `includeEnemyAabbs = true` (player only).
- `resolveCollision(pos, aabb)` → `resolveCircleAabb(pos, aabb, radius)`. Generic over radius.
- `moveAndCollide(dx, dz)` → `moveCircle(pos, dx, dz, radius, includeEnemyAabbs)`. Generic over position, radius, and whether enemy AABBs are tested. The `if (dx !== 0)` and `if (dz !== 0)` guards are removed: resolution always runs so a stationary entity still gets pushed out of overlap (e.g. heavy walking into idle player).
- `tick()` order is now: `updateEnemies(dt)` → `updateProjectiles(dt)` → `updatePlayer(dt)` → `updateWeaponTimers(dt)`. Enemies first so their new AABBs are visible to the player's collision pass this frame.
- `makeEnemy()` no longer pushes the AABB into `staticAABBs` and now initializes `position` (Vector3) and `attackCooldown` (number).
- `killEnemy()` no longer touches `staticAABBs` (the AABB was never in it).
- `tryFire()` / `tryReload()` early-return if `gameState !== PLAYING || !isLocked`.

**Known issues**
- Enemies walk through each other. v1 trade-off; clustering is acceptable for small wave sizes. If it becomes a problem, pass `includeEnemyAabbs = true` to enemy `moveCircle()` calls with self-exclusion.
- Enemies have no facing rotation. The symmetric body model hides this. Add `enemy.group.rotation.y = Math.atan2(dx, dz)` (or equivalent) once a front-of-body indicator exists.
- No pathfinding. Enemies can stall against cover-box corners when the player is directly behind a cover. Axis-separated collision slides them most of the time but not all; acceptable for arena scale.
- Projectile static collision is 2D — projectiles ignore obstacle height. Invisible in practice since shooter and player are both grounded and projectiles fly at chest height.
- Game-over restart is `location.reload()`. Fast (unpkg is cached) but the fullscreen permission prompt may reappear. Proper in-place restart with score lands in milestone 8. *(Resolved in milestone 8.)*
- No HUD bar yet — health is visible only via the damage vignette. *(Resolved in session 7.)*
- Auto-jump from m2 carries over: holding Space repeats jumps on landing. Acceptable; tune in polish.
